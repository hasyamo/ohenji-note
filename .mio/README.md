# .mio/ — 作業ログの受け渡し場所

このリポジトリでの作業を、はしゃもさんの Obsidian Vault（澪という別セッションが管理）に持ち帰るための橋渡しフォルダです。

## 作業の流れ（入口 → 作業 → 出口）

1. **入口（`handoff.md`）**：作業指示を受けたら、まず `handoff.md` に「目的・完了条件・やらないこと・止まって聞くこと」を書き、**はしゃもさんが一読して承認してから**作業を始めます。ズレていればここで直します。
2. **作業**：実装・修正・検証を進めます。
3. **出口（`result.md`）**：一区切りついたら `result.md` に結果を書きます。終了時、`result.md` の「結果」欄の冒頭に handoff の完了条件を転記して ○／× を付けてください（×は「未完了/失敗/中断」欄につながります）。

`handoff.md` と `result.md` はどちらもテンプレートが入っています。**見出しを増減させず**、その構成のまま埋めてください（後で別セッションが機械的に拾います）。

## status のルール

- `handoff.md` の status は **`active` / `done`** の2値のみ。
  - `active`：この発注に対応する作業が進行中
  - `done`：最終 `result.md` を `status: open` で書いた直後、自分（実装Bot）で `done` に変える（澪の回収時点ではない）
- `result.md` の status は **`open` / `collected`** の2値のみ（`done` は使わない）。
  - `open`：最終結果を書いた。澪の回収がまだ。成功・失敗・部分完了を問わない
  - `collected`：澪が回収済み。ここは澪だけが変更する
- **前回の `result.md` が `open` のまま残っている場合、新しい作業を始めない。** 澪がまだ回収していないだけなので、はしゃもさんに回収を依頼してから次を始めてください。
- `result.md` が `collected` になっていたら、新しい作業のために `handoff.md` / `result.md` 全体を上書きしてよい（1作業1回の上書き運用）。**回収前の内容を上書きで消さない。**

## 書くときの注意

- **完了条件は後から○×で判定できる形で**。「改善する」「整える」は禁止。「〜が表示される」「〜がデプロイされている」など観測できる形で書く。
- 「何をしたか」は実況ではなく要点で。差分の中身はコードとgit logが正なので、ここに再掲しなくていい。
- 未完了・中断がある場合は必ず埋める（「どこまで進んだか」「なぜ止まったか」が空だと、次のセッションが同じ調査からやり直すことになる）。
- 判断に迷って保留にしたことがあれば「判断・気づき」に書く。ここに書かれたものだけが Obsidian 側に伝わります。
- 「止まって聞くこと」に書いた判断は、**自走せず必ずはしゃもさんに確認してから**進めてください。

## これは何のためのフォルダか

はしゃもさんは複数プロジェクトを横断していて、各プロジェクトでの作業を「澪」という別セッションが定期的に回収し、Obsidian Vault に要約・記録しています。このリポジトリで動く Claude Code（あなた）はその運用を知らない前提なので、このフォルダとテンプレートだけ渡しています。澪の内部用語やVault側のルールを気にする必要はありません。テンプレートの見出しに沿って書くだけで大丈夫です。

（`handoff.md` / `result.md` は Git 管理外です。`README.md` だけコミットされます。）
